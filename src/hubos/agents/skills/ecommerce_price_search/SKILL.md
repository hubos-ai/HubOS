# 电商价格搜索与比价

这个 skill 不是一个底层搜索引擎，而是一个**电商价格调研工作流**。  
它负责统一协调这些已有能力：

- `web_crawl`：优先做公开搜索、抓取搜索结果页、抓取公开报价页
- `tavily_search`：做补充搜索、找公开文章或经销商报价页
- `browser_visible`：当页面需要人工参与、登录、看到真实页面时使用
- `browser_cdp`：当用户已经在本机 Chrome 里登录京东/淘宝/拼多多，希望复用登录态时使用

---

## 适用场景

- 查询某个商品在国内电商平台的大概价格
- 比较同一商品在京东 / 淘宝 / 拼多多 / 1688 的价格差异
- 查询某型号是否仍然在售
- 查询商品是公开价、活动价还是需要登录后才能看
- 输出一个**可用的价格区间**，而不是执着于单个平台详情页的精确最低价

---

## 目标输出

每次调研都尽量输出下面这些内容：

1. 商品名称 / 型号
2. 命中的平台或渠道
3. 价格或价格区间
4. 是否为公开可见价
5. 是否需要登录 / 浏览器态确认
6. 可信度判断
7. 给用户的简短结论

推荐输出格式：

```text
商品：3M VFS401-WM

渠道结果：
- 京东：未发现稳定公开在售价 / 商品页已下架 / 需登录确认
- 淘宝：约 999-1299 元（搜索结果页）
- 1688：约 850-1100 元（批发价，需注意起订量）
- 品牌/经销商：有销售记录，但未公开标价

结论：
- 当前公开可见价格主要集中在 900-1300 元区间
- 若要确认精确成交价，建议使用已登录浏览器进一步查看京东/淘宝详情页
```

## 工具优先级

### 零、先判断 Tavily 是否可用

`tavily_search` 不是默认永远可用。

只有在以下任一条件成立时才使用它：

- 已配置 `TAVILY_API_KEY`
- Agent 已启用 tavily MCP

如果不确定它是否可用：

- 默认视为不可用
- 直接跳过 `tavily_search`
- 不要向用户输出“tavily_search 函数不存在”这类内部错误
- 改用 `web_crawl`、`browser_visible`、`browser_cdp` 完成任务

### 一、优先：公开搜索

优先使用：

- `web_crawl`
- 必要时 `tavily_search`（仅在确认可用时）

优先搜这些内容：

- 商品型号 + 平台名
- 商品型号 + 价格
- 商品型号 + 经销商 / 报价 / 在售
- 商品型号 + site:jd.com / site:taobao.com / site:tmall.com / site:1688.com

例如：

```bash
node scripts/search.mjs "3M VFS401-WM 价格 中国" -n 8
node scripts/search.mjs "3M VFS401-WM 京东 淘宝 1688" -n 10
```

### 二、其次：抓搜索结果页或公开页

如果详情页被拦、要求登录、或页面无法提取：

- 不要卡死在详情页
- 改抓搜索结果页
- 改抓品牌页 / 经销商页 / 比价页 / 文章页

优先接受的信息：

- 搜索结果里的标价
- 列表页价格区间
- 公开招商/经销报价
- 线下渠道公开宣传价

### 三、最后：浏览器态

只有在这些情况才切换浏览器：

- 用户明确要查更精确的实时价
- 商品详情页必须登录才能看
- 页面是强 JS 渲染、且公开抓取看不到价格
- 用户愿意人工登录

这时优先级是：

1. `browser_visible`
   - 用户可以亲自看到浏览器
   - 可扫码登录
   - 适合演示、人工确认

2. `browser_cdp`
   - 用户已在本机 Chrome 登录
   - 需要复用现成 cookie / 登录态
   - 适合多次重复查询

## 国内电商平台的具体策略

### 京东

- 先搜京东搜索结果页，不优先详情页
- 如果详情页已下架，也要记录“曾有销售痕迹”
- 如果只搜到商品页但打不开价格，标记：
  - `需登录确认`
  - `公开价格不可稳定获取`

### 淘宝 / 天猫

- 优先搜索结果页和店铺页
- 商品详情页经常有风控、登录、滑块
- 能抓到搜索结果页价格就先给区间

### 拼多多

- 很多页面对无头访问不友好
- 优先把它作为参考渠道，而不是唯一价格依据

### 1688

- 很适合拿“批发价区间”
- 但要提醒用户：
  - 可能有起订量
  - 可能不是零售价

### 品牌官网 / 经销商

- 如果平台页不好读，品牌页和经销商页往往更稳定
- 对工业品、净水器、商用设备尤其重要

## 价格判断规则

### 可以直接给“明确价格”

前提：

- 同一平台公开页直接可见
- 或多个公开来源价格接近

### 更常见的是给“价格区间”

当出现以下情况时，优先给价格区间：

- 平台结果不一致
- 同一商品有套餐 / 赠品 / 规格差异
- 搜到的是批发价 + 零售价混合
- 部分页面需要登录

### 不要过度自信

如果证据不足，要明确写：

- `未查到稳定公开售价`
- `仅有销售记录，无公开报价`
- `需登录后进一步确认`

---

## 推荐工作流

### 工作流 A：快速查价格区间

适合：用户只想知道大概多少钱

1. 用 `web_crawl` 搜商品型号 + 价格 + 平台
2. 记录公开搜索结果中的价格
3. 用 `tavily_search` 补公开报价页（仅在确认可用时）
4. 输出 2-4 个渠道和一个价格区间

如果 `tavily_search` 不可用，则改为：

3. 用 `web_crawl` 补品牌页 / 经销商页 / 搜索结果页
4. 输出 2-4 个渠道和一个价格区间

### 工作流 B：多平台比价

适合：用户要对比京东 / 淘宝 / 1688 / 拼多多

1. 每个平台分别搜索一次
2. 不要求每个平台都抓详情页
3. 搜索结果页能拿到价格就先纳入
4. 标注零售价 / 批发价 / 登录可见价
5. 输出对比表

推荐对比表：

```text
| 平台 | 价格 | 说明 | 可信度 |
|------|------|------|--------|
| 京东 | 未稳定获取 | 商品页下架 / 需登录 | 中 |
| 淘宝 | 999-1299 元 | 搜索结果页 | 中 |
| 1688 | 850-1100 元 | 批发价，可能有起订量 | 中 |
| 经销商 | 未公开价 | 仅展示有销售 | 低 |
```

### 工作流 C：登录态精查

适合：用户真的要精确实时价

1. 先告诉用户要用浏览器态
2. 用 `browser_visible` 打开真实浏览器
3. 用户扫码登录
4. 再打开目标平台详情页或搜索页
5. 读取页面价格并输出

如果用户已有登录 Chrome：

1. 用 `browser_cdp` 连接已有浏览器
2. 打开对应页面
3. 复用登录态读取价格

---

## 失败时的降级规则

当详情页不可访问时：

1. 改抓搜索结果页
2. 改抓店铺页
3. 改抓品牌/经销商页
4. 输出“公开价格区间”
5. 明确说明需要浏览器态才能确认最终价

不要出现这种失败模式：

- 一直重复尝试单个详情页
- 因为平台要求登录就直接说“无法搜索”
- 因为 `tavily_search` 不可用就中断整个任务
- 明明可以给区间，却完全不给结果

---

## 使用原则

### 应该做的

- 优先给出可用的价格区间
- 优先公开来源
- 标注价格类型和可信度
- 对国内平台的登录限制保持诚实
- 需要时主动建议浏览器态确认

### 不应该做的

- 把搜索结果页价格说成绝对成交价
- 忽略批发价和零售价的差别
- 遇到登录限制就停止所有分析
- 明明没有充分证据却给出非常精确的单一价格

---

## 结论模板

### 模板 1：已有区间

```text
我查到这个商品在国内是有销售痕迹的。
目前公开可见价格主要集中在 X-Y 元之间。
其中 A 平台偏零售价，B 平台更像批发价或经销价。
如果你要确认最终成交价，建议再用已登录浏览器查看目标平台详情页。
```

### 模板 2：公开价不足

```text
我搜到了这个型号在国内的销售记录，但没有查到稳定公开售价。
目前更可靠的信息是：它确实在京东/经销商渠道出现过，但详情价需要登录或页面已下架。
如果你要，我下一步可以改用浏览器态帮你继续确认。
```
